# Green baseline diagnosis — scroll integrity

## Scope and current evidence

- **Observed (2026-09-17):** the worktree at `700428e` is clean before this report. `npm.cmd test` passed **158/158** in 27.0 s. Both focused commands also passed: `node --test test/negocia-bem-scroll-integrity.test.js` (4/4) and `node --test test/sticky-scroll-integrity.test.js` (1/1).
- **Observed:** the previous failure output cannot be reproduced against the current artifact with its remote dependencies available. It is therefore not evidence of a presently persistent CSS/JS regression.
- Strongest failure mode: these tests execute production HTML that depends on mutable third-party network resources, but neither test makes that dependency deterministic or reports its availability. A CDN/network failure produces the reported assertions exactly.

## Findings

### 1. Negocia Bem Probe 1 & 5 — active tab assertion

- **Observed:** `clientes/negocia-bem/site/index.html:2013-2039` registers the active-state update exclusively through `ScrollTrigger.create`; the initial markup at `:1052` makes state 0 active.
- **Observed:** GSAP and ScrollTrigger are remote scripts at `index.html:12-13`; the test only waits a fixed 500 ms after `domcontentloaded` (`test/negocia-bem-scroll-integrity.test.js:56-57`). With normal network access, the focused test passes.
- **Observed (controlled disconfirmation):** blocking `**/gsap@3/**` leaves `window.gsap` and `window.ScrollTrigger` undefined and leaves the active state at index 0 after the probe's scroll. That is the exact condition that fails `activeIndex50 >= 1` at test line 94.
- **Inferred root cause:** unavailable/changed remote GSAP runtime (or a runtime load error) is the likely cause of the reported active-tab failure, not a current change to the tab calculation. The test's fixed delay does not establish that the dependency and its triggers are ready.
- **History:** the relevant ScrollTrigger code is attributed to `9e65838` (2026-09-03). The test predates the later Negocia Bem artifact edits (`b9065e2`/`5ed6e53`, 2026-09-15), but the selector and behavior still pass now. It is **not proven stale**; it is environment-coupled.

### 2. Negocia Bem Probe 3 — 769 px desktop/mobile assertion

- **Observed:** mobile-only rules in `index.html:358-361` hide `.nb-desktop` and show `.nb-mobile` only at `max-width: 767px`. At 769 px, hiding `.nb-mobile` relies on the Tailwind `hidden` class in the markup (`:1135`), generated by the remote Tailwind browser compiler at `:14`.
- **Observed (controlled disconfirmation):** at 769 px with the Tailwind browser request blocked, computed display is `{ desktop: 'block', mobile: 'block' }`; this exactly fails test line 184 (`desktop visible && mobile hidden`). With the dependency available, the focused probe passes.
- **Inferred root cause:** a missing/blocked/altered Tailwind browser runtime, rather than a wrong 768 px threshold in the local CSS. The asserted desktop/mobile contract is not locally encoded above 767 px.
- **History:** the local mobile breakpoint and its behavior are attributed to `9e65838`; no post-test change was found that contradicts the expected 769 px behavior. This is best classified as an environment-sensitive test/artifact dependency, not a confirmed regression.

### 3. SCALEX sticky `.service-card._01` observed as `static`

- **Observed:** `clientes/flashtech-caso-04-growth/site/index.html:5` imports the only stylesheet that supplies the exported SCALEX layout from `https://cdn.prod.website-files.com/.../acilav.webflow.shared.379082d56.css`. The integrity test opens the HTML by `file:///` and samples computed styles after a fixed 500 ms (`test/sticky-scroll-integrity.test.js:18-23`).
- **Observed:** with the stylesheet available in this run (HTTP 200), `.service-card._01`, all service cards, and `.insight-scroll-area` compute to `position: sticky`; the focused test passes.
- **Observed (controlled disconfirmation):** blocking that one stylesheet makes `.service-card._01` and `.insight-scroll-area` compute to `position: static`, matching the reported failure exactly.
- **Inferred root cause:** unavailable/changed remote Webflow stylesheet, not a current local change that removed sticky positioning. `git` shows the SCALEX artifact was added in `5a8a662` (2026-09-01) and the sticky test in `9e65838` (2026-09-03), with no later change to that artifact.

## Do these failures share a cause?

**Yes, at the reliability boundary:** all three require a remote, mutable runtime asset but are evaluated as local artifacts without dependency readiness or network evidence. They have different upstream resources (GSAP/ScrollTrigger, Tailwind browser compiler, Webflow stylesheet), so one resource outage does not technically cause all failures; the common defect is non-self-contained artifact/test setup.

## Minimal safe repair scope

1. **Negocia Bem artifact determinism** — `clientes/negocia-bem/site/index.html` plus locally versioned assets (compiled Tailwind CSS; pinned local GSAP and ScrollTrigger, or equivalent local no-library state update). Replace the remote runtime references. A narrow CSS fallback alone can fix the 769 px assertion, but cannot safely restore the scroll-driven contract if Tailwind/GSAP is absent.
2. **Negocia Bem regression evidence** — `test/negocia-bem-scroll-integrity.test.js`: serve only local client assets, wait for explicit application/ScrollTrigger readiness instead of sleeps, and fail with a diagnostic if a remote script/style request is required. Keep the 769/767 and active-index assertions.
3. **SCALEX artifact determinism** — `clientes/flashtech-caso-04-growth/site/index.html` plus a versioned local copy of the exact exported Webflow stylesheet (and its needed referenced assets). Do not merely add a `position: sticky` override: that would mask the missing layout contract.
4. **SCALEX regression evidence** — `test/sticky-scroll-integrity.test.js`: serve the client from a local HTTP fixture/server, assert the required local stylesheet is loaded, then retain computed sticky and overflow checks.

## Recommended task split

- **Task A — Negocia Bem builder:** localize/pin runtime assets, preserve the existing visual/breakpoint contract, and add an explicit readiness signal.
- **Task B — SCALEX builder:** vendor the Webflow stylesheet and verify the export's dependency chain is local.
- **Task C — independent verifier:** update the two tests to run with external requests blocked or rejected, rerun focused tests and `npm.cmd test`, and report the actual loaded asset URLs/statuses on failure.

Tasks A and B are independent. Task C should follow both so it verifies the same immutable local artifacts rather than reintroducing a network dependency.
